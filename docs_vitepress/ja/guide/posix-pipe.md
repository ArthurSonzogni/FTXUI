# FTXUI での POSIX パイプ入力

::: warning 対応プラットフォーム
この機能は Linux および macOS でのみ動作します。Windows や WebAssembly ではサポートされていません。
:::

## POSIX パイプとは

POSIX パイプは、2つの別々のプログラム間でデータをやり取りする仕組みです。一方のプログラムの出力を、もう一方のプログラムの入力へ直接渡すことができます。データが流れる一方向の管のようなものです。

**例:**

ファイル一覧を取得し、それを対話的にフィルタリングしたい場合を考えます。

- `ls`: ファイル一覧を出力する。
- `interactive_grep`: テキストをフィルタリングしつつキーボード入力を受け付ける FTXUI アプリケーション。

これらをパイプ（`|`）でつなぐことができます。

```bash
ls -l | interactive_grep
```

このときの流れは次のとおりです。
1. `ls -l` がファイルの詳細一覧を出力します。
2. `|` がその一覧を `interactive_grep` へ直接渡します。
3. `interactive_grep` は一覧を受け取って表示します。FTXUI アプリケーションであるため、`ls` から初期データを受け取りつつも、そのままキーボードで入力して一覧を絞り込むことができます。

## FTXUI がパイプ入力を処理する仕組み

FTXUI では、パイプ経由で他のプログラムからデータを読み込みながら、同時にキーボードによる対話操作を続けることができます。データを処理するインタラクティブなコマンドラインツールを作る際に便利です。

通常、FTXUI アプリケーションはすべての入力を `stdin` から受け取ります。しかし、`stdin` がパイプの出力に接続されている（つまりアプリケーションへデータがパイプ入力されている）ことを検出すると、FTXUI は自動的に対話用のキーボード入力の読み込み先を `/dev/tty` へ切り替えます。これにより、パイプからのデータを処理しながらユーザー入力も受け取ることができます。

この機能は**デフォルトで有効**になっています。

パイプ入力を読み込みつつキーボード操作にも応答させたい場合、特別な設定は不要です。

```cpp
auto app = App::Fullscreen();
// app.HandlePipedInput(true); // Enabled by default
app.Loop(component);
```

## パイプ入力処理を無効にする

この機能が不要な場合や、独自の入力処理と競合する場合は、メインループを開始する前に `HandlePipedInput(false)` を呼び出してください。

```cpp
auto app = App::Fullscreen();
app.HandlePipedInput(false);
app.Loop(component);
```
